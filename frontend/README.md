# Aéza Churn Risk Analyzer

Локальный демонстрационный фронтенд: React 19, TypeScript, Vite, Tailwind CSS 4, shadcn/ui Button (Radix Slot + CVA), Recharts, Lucide и React Router.

## Запуск

```sh
npm install
npm run dev
```

```sh
npm run build
npm test
```

Vite слушает `http://127.0.0.1:5173`. Production-сборка находится в `dist/`. Для BrowserRouter хостинг должен возвращать index.html для неизвестных путей.

## Архитектура

- `pages`: Dashboard, Snapshot, Historical, Settings.
- `components`: UI, панели, статусы, GradientASCII из приложенного промпта React Bits (очистка WebGL адаптирована для StrictMode). Полноэкранный ASCII-фон общий для всех страниц, панели полупрозрачные в тёмной медной гамме.
- `features/risk`: чистая функция расчёта и тесты.
- `services`: интерфейс AnalyzerApi, Mock API и REST-адаптер HttpApi.
- `types`: DTO и модели настроек.
- `hooks`: асинхронная загрузка, ошибки, сохранение и состояние приложения.
- `lib`: форматирование и вспомогательные функции.
- `mocks`: воспроизводимые 10 аккаунтов, 30 услуг, 100 транзакций.

## Модель

Все суммы в DTO — целые евроценты. UI форматирует их в евро. Дата среза фиксирована: 23 октября 2026, чтобы демо оставалось воспроизводимым. Нет выдуманной временной динамики.

Risk Score = round(sum(severity × weight) / sum(weights) × 100). Пять признаков: дефицит баланса относительно ближайших продлений, близость продления, доля услуг без автопродления, доля приостановленных услуг, доля неуспешных транзакций за 30 дней. Подробные формулы видны в Snapshot. Это эвристический индекс, не обученная вероятность оттока. Выручка под риском — месячная стоимость незакрытых услуг клиентов высокого риска, не прогноз финансовых потерь.

Dashboard: поиск по ID/email/имени, фильтр уровня, двусторонняя сортировка всех столбцов, пагинация и CSV-экспорт отфильтрованных данных. Переходы к конкретному клиенту сохраняют его ID в URL.

Snapshot: выбор клиента, вклады факторов и формулы, услуги, транзакции, редактирование баланса и переключение автопродления. Изменения сразу пересчитывают риск.

Historical: ежедневных снимков нет. Корректно показывает отсутствие данных и причину остановки анализа. Транзакции сами по себе не восстанавливают историю баланса или услуг. Автоматический сбор снимков и историческая модель требуют будущего API.

Settings: валидация порогов и параметров, нормализация весов, сохранение и сброс формы к значениям по умолчанию. Настройки и изменения исходных данных хранятся в localStorage (`aeza-settings-v1`, `aeza-data-v1`). Для возврата к исходным данным удалите эти два ключа в DevTools. Ошибки чтения и записи показаны в UI.

## Подключение Rust REST API

В `useAnalyzer.tsx` замените `mockApi` экземпляром `new HttpApi(baseUrl)`. Контракт: GET /dataset → Dataset; GET /settings → Settings; PUT /settings и PUT /dataset → 204 или JSON. Для production следует заменить демонстрационный PUT /dataset точечными PATCH-эндпоинтами, добавить авторизацию и серверную валидацию. Страницы зависят от общего интерфейса, а не от localStorage.
