# Экономическое тестирование Market Simulator

Дата проверки: **23 октября 2026**, Europe/Moscow. Проект: `/Users/timofej/Desktop/aeza/aeza-intelligence`. Исправленная версия правил: **market-v1.1**.

## Итог

**Все итоговые проверки прошли.** 75 экономических сценариев выполнены отдельно в Rust-движке и через реальные TCP/HTTP-соединения. Для каждого пути дополнительно выполнены 9 сравнительных проверок: **84 записи на путь, 168 записей суммарно**. Это 75 сценариев, а не 168 разных рынков. Все входы используют seed **42**.

Полный `cargo test` содержит **22 тестовые функции**: 17 прежних тестов, 3 регрессии и 2 функции, запускающие экономические матрицы. Для HTTP-матрицы выполнены по 2 POST и 2 GET на сценарий — 300 сетевых запросов. Дополнительно стандартный исполняемый сервер на `127.0.0.1:8091` прошёл **25 сценариев / 54 HTTP-запроса**, включая ноль покупателей и все изменения цен при трёх чувствительностях.

Проверка HTTP-матрицы не подменяет ответы: Axum слушает настоящие ephemeral loopback-порты. Используется тот же обработчик, что в приложении, с неизменяемым каталогом, переданным при создании сервера. Каталоги контролируемых тестов явно сценарные; отдельные 21 сценарий используют сохранённые 322 наблюдаемых тарифа. Штатный сервер использует обычный каталог; через HTTP заменить его нельзя. Метаданные внедрённого каталога не выдаются за исходный VPS Price Index.

По каждому сценарию записаны ожидание, фактические помесячные результаты, seed, параметры, хеши и PASS/FAIL. См. [полную матрицу](case-details.md), [Rust JSON](engine-results.json), [HTTP JSON](http-results.json) и [проверку штатного сервера](standalone-http.json).

## Контрольный рынок с точным ожидаемым результатом

20 новых покупателей в месяц, 3 месяца; бюджет $30, preference=0, отток=0, трение=0. Базовая Aéza стоит $10, конкурент с такими же ресурсами — $11.50. Fixed=$100/мес., variable=$3/аренду. Здесь все три чувствительности выбирают одну и ту же более дешёвую доступную альтернативу. У Aéza 20/40/60 аренд, пока она дешевле конкурента; при цене $12/$14 — 0/0/0. Отсутствие разнообразия в этом контроле задано специально; неоднородность проверяется на наблюдаемом каталоге и в отдельных outside-тестах.

| Цена Aéza | Аренды в последнем месяце | Выручка за 3 месяца, $ | Прибыль за 3 месяца, $ |
|---|---:|---:|---:|
| −40% | 60 | 720.00 | 60.00 |
| −20% | 60 | 960.00 | 300.00 |
| −10% | 60 | 1 080.00 | 420.00 |
| Без изменения | 60 | 1 200.00 | 540.00 |
| +10% | 60 | 1 320.00 | 660.00 |
| +20% | 0 | 0.00 | -300.00 |
| +40% | 0 | 0.00 | -300.00 |

Скидка уменьшает выручку в этом контроле, поскольку число аренд уже максимально. Тест не требует обязательного роста прибыли. После проигрыша конкуренту сохраняется убыток $300 за три месяца фиксированных расходов.

## Наблюдаемый каталог: пример средней чувствительности

30 базовых новых покупателей в месяц, шесть месяцев с весами Akash из примера, seed 42; остальные исходные параметры одинаковы. Это сценарный эксперимент на сохранённом прайсе, не рыночный прогноз.

| Изменение цены | Аренды Aéza в последнем месяце | Выручка за 6 месяцев, $ | Прибыль за 6 месяцев, $ |
|---|---:|---:|---:|
| −40% | 106 | 1 899.00 | 222.00 |
| −20% | 75 | 2 008.00 | 628.00 |
| −10% | 66 | 1 984.50 | 706.50 |
| Без изменения | 51 | 1 885.00 | 742.00 |
| +10% | 43 | 1 666.50 | 640.50 |
| +20% | 32 | 1 368.00 | 459.00 |
| +40% | 21 | 1 064.00 | 269.00 |

Скидка 40% увеличила аренды с 51 до 106, но снизила прибыль с $742 до $222. Это корректный результат, а не провал теста. Прибыль не упорядочивается ни по скидке, ни по чувствительности. Из собственных ценовых закономерностей проверена только неувеличивающаяся функция спроса **первого периода** при росте собственной цены, фиксированных покупателях и остальных полезностях.

## Проверенные балансы

Для каждого провайдера и месяца:

- active(t) + switches_out + churn_outside = active(t−1) + new + switches_in;
- active = renewals + new + switches_in;
- active(t−1) = renewals + switches_out + churn_outside;
- суммарные switches_in = суммарным switches_out;
- active рынка + outside = накопленные покупатели; приток соответствует округлённому buyers_per_month × weight;
- доля провайдера = его active / active рынка, сумма долей 1; при пустом рынке все доли 0;
- при одном доступном ценовом уровне выручка независимо проверяется как цена × аренды; для нескольких уровней проверяются границы цен и отдельный точный ресурсный контроль $400/$800/$1200;
- cost Aéza = fixed + variable × active, profit = revenue − cost; накопленные суммы равны сумме месяцев. Неизвестные расходы/прибыль конкурентов остаются null.

Финансовые равенства проверяются с допуском max(1e−7 USD, 1e−10 × величина); счётчики — строго, битовое восстановление JSON — строго. Повтор каждого входа с тем же seed даёт идентичный результат, включая байты HTTP JSON. HTTP-ответы также полностью сравниваются с прямым Rust-расчётом.

## Ограничения модели, обнаруженные и подтверждённые тестами

1. **Денежных остатков покупателей нет.** Бюджет — месячный предел цены, а не банковский баланс. Проверены количество клиентов/аренд и соблюдение доступности, но модель не может проверить пополнение кошелька, накопление долга или исчерпание остатка. Сумма оплат за несколько месяцев может превышать один месячный бюджет.
2. Один покупатель арендует максимум один VPS. Ёмкость провайдеров и физическая загрузка не ограничены; рост спроса не увеличивает предельные затраты автоматически.
3. Уход означает текущий период без аренды, а не постоянное исчезновение с рынка. Клиент может вернуться. Поэтому 100% уход при 20 новых клиентах даёт 20/20/40 активных аренд, а не 20/20/20; нельзя навязывать монотонность поздних запасов при любом churn.
4. `switching_cost_utility` — штраф полезности, не долларовая комиссия. Он действует при смене любого провайдера, а не только при выходе из Aéza. Выручку или расходы он непосредственно не увеличивает.
5. Продления переоцениваются по текущей цене полностью, без grandfathering, ежедневного prorating и бесплатных периодов.
6. Прибыль сценарная: одинаковая variable cost на аренду плюс fixed. Нет самостоятельных CAPEX, налогов, комиссий, платы за переход, полной бухгалтерии или различающейся себестоимости тарифов. Отрицательная прибыль допустима.
7. Цена выбирается через заданное правило utility; beta, предпочтения, отток и бюджеты не оценены причинно по продажам. Akash определяет только сценарную форму притока. Числа не доказывают реальную эластичность рынка VPS.
8. Доля считается среди активных аренд, исключая outside. Изменение outside меняет знаменатель: доля и абсолютный спрос могут двигаться по-разному. Суммарные события ухода не равны числу уникальных ушедших клиентов.
9. При точном равенстве utility порядок ID всё ещё служит условной развязкой, а не вероятностным выбором; это теперь явное и согласованное правило, а не скрытое предпочтение конкурентам.
10. Денежная арифметика остаётся f64. JSON больше не теряет биты, но арифметические погрешности и различия между платформами полностью не исключены. Это не реализация биллинга с целыми центами.
11. Валидация требует непустого каталога и хотя бы одного предложения Aéza; «нет подходящих тарифов» проверяется на валидном каталоге без допустимых предложений, а не как отсутствие самого каталога.

## Повтор тестирования

Из корня проекта:

```sh
MARKET_TEST_REPORT_DIR=/tmp/aeza-economics cargo test --locked --manifest-path market-simulator/Cargo.toml -- --nocapture
cargo clippy --locked --manifest-path market-simulator/Cargo.toml --all-targets -- -D warnings
cargo run --locked --manifest-path market-simulator/Cargo.toml
# В другом терминале:
python3 market-simulator/scripts/check_economics_http.py --engine-results /tmp/aeza-economics/engine-results.json --output /tmp/aeza-economics/standalone-http.json
```

Тесты настоящего TCP требуют разрешённого localhost. Зависимости зафиксированы Cargo.lock; на этой машине тесты прошли с `--offline --locked`. Существующие ML-модели и их контракты не изменялись. В frontend изменён только нижний предел числа покупателей на 0, в соответствии с исправлением API; регрессионные frontend-тесты сохранены.
