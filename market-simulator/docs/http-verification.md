Дата: 23 октября 2026, Europe/Moscow. Проверяемая копия проекта: `/Users/timofej/Desktop/aeza/aeza-intelligence`. API: `http://127.0.0.1:8091/api/market/v1`. ## HTTP-аудит

Скрипт `market-simulator/scripts/check_http.py` выполняет 13 групп проверок. Артефакты: `http-summary.json`, `comparison-response.json`.

1. GET health/catalog/example/sources/openapi; каталог содержит 322 плана.
2. POST 4 стратегии × 3 чувствительности, 6 месяцев. Для всех провайдеров/периодов независимо проверены:
   - active(t) = active(t−1) + new + switches_in − switches_out − churn_to_outside;
   - active = new + renewals + switches_in;
   - active(t−1) = renewals + switches_out + churn_to_outside;
   - сумма входящих переходов = сумме исходящих;
   - active + outside = cumulative_buyers;
   - доли суммируются в 1 при ненулевом рынке, иначе в 0;
   - cost = fixed + variable × active; profit = revenue − cost;
   - накопленные revenue/profit равны сумме месячных.
3. Повторный POST идентичен исходному JSON.
4. Контрольный рынок с единственным доступным тарифом: $5, 20 новых покупателей за месяц, без оттока. Активные аренды 20/40/60; выручка $100/$200/$300.
5. Цена во 2–3 месяце повышена до $10: выручка $100/$400/$600, подтверждено применение цены к продлениям.
6. Цена выходит за бюджет: аренды обнуляются, предыдущие аренды уходят, фиксированный расход остаётся.
7. 100% базовый уход: все прошлые аренды прекращаются на текущий период. Возвращение возможно в следующем.
8. Вероятностный отток с seed: stock-flow баланс сохраняется.
9. Изменение затрат влияет на прибыль и не меняет выбор покупателей.
10. Три чувствительности: контрольный тариф доступен по бюджету, но при высокой чувствительности utility ниже outside option.
11. Повышение цены Aéza вызывает наблюдаемые в ответе переходы к конкурентам, а не только сокращение собственной базы.
12. Стратегии с одинаковыми ценами дают одинаковые траектории.
13. Недопустимые horizon/churn/population возвращают HTTP 422.

## Результаты в браузере

Браузер: встроенный браузер Codex; взаимодействие через настоящие поля, кнопки и скачивание JSON. Самостоятельный headless Chromium не запустился из-за sandbox macOS; визуальная проверка выполнена во встроенном браузере.

При default seed 42, средней чувствительности и базовой стратегии:

| Условие | Аренды в последнем месяце | Выручка за 6 месяцев | Прибыль за 6 месяцев |
|---|---:|---:|---:|
| Исходные цены $5 / $10 / $20 | 146 | $6 225 | $3 966 |
| Первый тариф $25, остальные прежние | 123 | $5 830 | $3 808 |

Скачанные UI JSON сохранены как `browser-baseline-response.json`, `browser-price-change-response.json`. Они независимо повторно отправлены в Rust API; ответы полностью совпали. Для комбинации «бюджеты −30%, своя стратегия 80%, уход 100%, fixed cost $1000» получены 15 комбинаций, сохранён `browser-budget-churn-response.json`; все параметры присутствуют в echo scenario ответа. Для baseline/medium в этом сценарии прибыль −$3428 — отрицательные значения корректно показываются.

Проверено:

- До первого POST метрик и графиков нет.
- Изменение цены помечает прежний результат как устаревший, а не меняет его локально.
- Свежий успешный ответ убирает пометку. Найдена и исправлена ошибка сравнения JSON-полей с разным порядком; добавлены 2 регрессионных теста.
- Выбор ровного притока и снижения бюджетов, своей стратегии, оттока и затрат применяется сервером.
- JSON экспортирует серверный отчет целиком с исходным сценарием и replay hash.
- Три графика, таблица 12/15 комбинаций и подробные переходы/отток заполняются из ответа.
- Реальное завершение Rust-процесса: следующий POST показывает ошибку, сохраняет прежний результат и не генерирует замену. Reload без сервиса показывает экран недоступности API.
- Восстановление API и кнопка подключения возвращают рабочее состояние.
- Ширина viewport 390 px: document scrollWidth = 390; графики присутствуют, таблицы прокручиваются внутри контейнеров.
- Snapshot/Historical остаются доступны; код моделей не изменён.
- В успешном браузерном прогоне ошибок JavaScript не было. При отключенном сервисе ожидаемо появились сетевые ошибки.

## Экономическая интерпретация

Арифметических противоречий в проверенных сценариях не обнаружено. Это не подтверждает эмпирическую точность экономической модели.

- Спрос — активные аренды, не число новых покупателей. New leases включает реактивации.
- Уход из Aéza = switches_out + churn_to_outside. Его доля делится на предыдущий активный портфель. Сумма событий ухода за несколько месяцев может превышать число уникальных покупателей; UI подписывает это как события.
- По умолчанию ёмкость не ограничена, один покупатель арендует один сервер; постоянного ухода с рынка нет. Churn означает период без аренды и допускает реактивацию.
- Цены Aéza применяются ко всему портфелю каждый период, без grandfathering и prorating.
- Себестоимость задана одной суммой на аренду; разные конфигурации могут иметь разную фактическую стоимость. Прибыль сценарная: fixed + variable, без отдельных налогов/CAPEX/комиссий.
- Ценовая чувствительность задаётся правилом utility, не оценена причинно на исторических продажах. Уровни нужны для stress testing, а не интервала уверенности прогноза.
- Akash задаёт только форму агрегированного притока; размер VPS рынка, бюджеты, вероятность ухода и тарифы Aéza остаются допущениями. Повтор 6-месячной формы после 6-го периода в UI явно обозначен.
- Stock, CPU performance, налоги, IP и региональная совместимость прайсов не подтверждены полностью.

## Запуск и повтор проверки

Из корня проекта:

```sh
cargo run --locked --manifest-path market-simulator/Cargo.toml
# В другом терминале:
cd frontend
npm ci
npm run dev -- --port 5178
# Открыть http://127.0.0.1:5178/market
```

```sh
python3 market-simulator/scripts/check_http.py --output /tmp/aeza-http-audit
cargo test --locked --manifest-path market-simulator/Cargo.toml
cd frontend
npm test
npm run build
```

Для production SPA сервер должен обслуживать fallback на index.html и проксировать `/api/market` к Rust-сервису. Vite proxy включён для dev и preview, но не является конфигурацией промышленного reverse proxy. По умолчанию Rust привязан к loopback.
