# Automated test coverage

Run the offline suites from the repository root:

```sh
cargo test --locked --offline
cargo run --locked --offline --bin model_smoke -- scripts/fixtures/full_model_stress/model_history.json
cargo test --manifest-path market-simulator/Cargo.toml --locked --offline
cd frontend && npm test && npm run build
```

The PostgreSQL-backed v1 HTTP suite needs its own empty, disposable database:

```sh
V1_API_TEST_DATABASE_URL=postgres://user:password@127.0.0.1:5432/aeza_v1_api_test \
  cargo test --locked --test v1_api -- --nocapture
```

It refuses to run when the database already has client accounts. CI also provides separate empty databases through `TEST_DATABASE_URL` for snapshot replacement and `MARKET_TEST_DATABASE_URL` for tariff observation persistence.

The simulator suite opens an ephemeral localhost port for its HTTP matrix test. Run it outside environments that prohibit local socket binding.

The isolated Compose acceptance job runs `scripts/check_auth.sh`, `scripts/check_performance.sh`, `scripts/check_compose_stack.sh`, and `scripts/browser_acceptance.mjs` after building a disposable stack. The browser script needs Chromium, Node 22+, and test operator credentials; it navigates the actual SSO callback and exercises the running UI.

Database fixtures are intentionally guarded: `scripts/check_clean_fixture_db.sh` refuses to run unless `DATABASE_URL` points to an empty database. The direct replacement integration test clears client rows, so set `TEST_DATABASE_URL` only to a disposable database. The HTTP suite similarly requires a dedicated empty database through `V1_API_TEST_DATABASE_URL`.
