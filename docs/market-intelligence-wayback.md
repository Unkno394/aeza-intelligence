# Market Intelligence: история тарифов через Wayback Machine

## Источники

Начальный список страниц хранится в `providers.tariff_page_urls`. Один
провайдер может иметь несколько URL: страницы тарифов и их адреса меняются
со временем. Тип тарифов, валюта, регион и версия парсера определяются
адаптером провайдера и проверяются при разборе.

Источники: [FirstVDS](https://firstvds.ru/docs/tariffs.html),
[Timeweb Cloud](https://timeweb.cloud/services/vds-vps),
[Selectel](https://selectel.ru/services/cloud/vps-vds/) и страницы
[Hetzner Cloud](https://www.hetzner.com/cloud/regular-performance/).

Для перечисления архивных снимков нужен [CDX Server API](https://github.com/internetarchive/wayback/blob/master/wayback-cdx-server/README.md).
`Availability API` возвращает ближайший снимок и не подходит для построения
всей истории. Запрос CDX использует `url`, `output=json`, поля
`timestamp,original,mimetype,statuscode,digest`, диапазон дат и фильтры
`statuscode:200`, `mimetype:text/html`. Ответ JSON начинается со строки
заголовков. При большом количестве снимков нужен `resumeKey` или пагинация.

По найденной записи скачиваем страницу конкретного снимка и сохраняем вместе
с извлечённой ценой фактический URL ответа, дату снимка и CDX digest. Снимки с одинаковым
`digest` можно пропускать после проверки, но CDX `collapse=digest` удаляет
только соседние дубликаты. Пустой список CDX означает отсутствие доступных
снимков по указанному URL, а не доказательство неизменной цены.

Текущие тарифы собираются отдельно с официальных страниц или API провайдеров.
Архивная дата обозначает время наблюдения цены в снимке; фактическая дата
введения цены может быть иной.

## Пайплайн

1. Планировщик берёт включённые URL и ищет новые записи CDX.
2. Загрузчик получает HTML, ограничивая частоту запросов и повторяя временные
   ошибки с паузой. Ссылка и дата снимка переходят в запись цены.
3. Парсер, выбранный по провайдеру и версии страницы, извлекает тарифы.
4. Валидатор проверяет цену, валюту, период оплаты и достаточность CPU/RAM/диска.
   Частичный результат остаётся помеченным `incomplete` и не попадает в
   автоматическое сравнение цен.
5. Текущие страницы проходят через тот же формат предложений с источником
   `live`. Сравнение выполняется только для сопоставимых периода оплаты,
   валюты, региона, типа диска и условий НДС. Для сравнения разных валют
   понадобится курс на дату наблюдения; исходная цена остаётся без пересчёта.

Парсер должен быть отдельным для FirstVDS, Timeweb Cloud и Hetzner. При
изменении структуры страницы архивный снимок можно повторно скачать и
разобрать новой версией парсера. Неизвестную цену нельзя заменять нулём или
последней известной ценой.

## Таблицы в существующем PostgreSQL

[Миграция](../migrations/001_market_intelligence.sql) создаёт схему
`market_intelligence` в той же базе, где хранится остальная аналитика Aéza.
Отдельная база не нужна.

| Таблица | Содержимое |
| --- | --- |
| `market_intelligence.providers` | FirstVDS, Timeweb Cloud, Hetzner, адреса сайтов и страницы тарифов для обхода. |
| `market_intelligence.provider_tariffs` | Название и характеристики тарифа: CPU, RAM, диск, регион и дополнительные параметры в `attributes`. Изменение конфигурации создаёт новую версию строки; старые цены продолжают ссылаться на прежние характеристики. |
| `market_intelligence.tariff_prices` | Каждая зафиксированная цена, валюта, период оплаты, дата наблюдения и происхождение (`archive` или `live`). Цена 2024 года остаётся после добавления снимка 2025 года. |

`observed_at` для Wayback равен времени архивного снимка, для прямого парсинга —
времени обхода сайта. `effective_at` заполняется только если провайдер прямо
указал дату вступления цены в силу. `observation_key` делает повторный импорт
одного и того же снимка идемпотентным. Цена хранится в минимальных единицах
валюты, например копейках или евроцентах. `parse_status = 'incomplete'`
сохраняет частичный результат, но аналитика цен выбирает только `complete`.

Полный HTML отдельной таблицей не хранится: в `tariff_prices` остаются
`source_url`, `archive_url`, `cdx_digest`, версия парсера и текстовый фрагмент
для проверки. Если понадобится повторно разбирать архив без новой загрузки,
можно добавить таблицу исходных снимков в этой же схеме.

Базовая выборка для графика цены одного тарифа:

```sql
SELECT t.plan_name, p.observed_at, p.price_minor, p.currency,
       p.billing_period, p.source_kind
FROM market_intelligence.provider_tariffs AS t
JOIN market_intelligence.tariff_prices AS p
  ON p.provider_tariff_id = t.id
WHERE t.provider_id = $1
  AND t.plan_key = $2
  AND p.parse_status = 'complete'
ORDER BY p.observed_at;
```

## Запуск

`cargo run --bin market_import -- inspect --provider selectel --file page.html`
проверяет разбор локально сохранённой страницы без БД. Для сбора:

```sh
DATABASE_URL='postgres://...' cargo run --bin market_import -- run --mode both
```

Команда применяет миграцию в указанной существующей БД, загружает текущие
страницы и до четырёх архивных снимков на URL по умолчанию, затем выводит
число записей в PostgreSQL. Для ограниченного запуска доступны `--provider`,
`--mode`, `--from-year`, `--max-archives` и `--delay-ms`. Страницы без полных
тарифов отмечаются ошибкой; извлечённые частичные тарифы сохраняются вместе
с полными из того же источника. Полностью пустой источник требует изменения
парсера или URL.

Разбор проверен на текущих страницах всех четырёх провайдеров и архивных
страницах Timeweb Cloud (2024), Selectel (2026), Hetzner (2024). Архив
FirstVDS пока не подтверждён: запрос CDX завершился тайм-аутом. Миграция и
запись в PostgreSQL ещё не проверены: в этой рабочей папке нет доступа к
существующему подключению. Фронтенд использует моковые данные.
